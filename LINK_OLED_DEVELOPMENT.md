# CannonKeys Link custom OLED firmware

Use `feature/link-oled` in both this firmware repository and
[svenski88/qmk_userspace](https://github.com/svenski88/qmk_userspace/tree/feature/link-oled).
The firmware branch starts from official QMK `develop` at `1aa377f6c7b`.
The implementation lives in userspace; no keyboard-level code changes are needed.
WT75-C work remains on firmware `feature/wt75-c-led-matrix` and userspace `main`.

## Dashboard

Each portrait 64x128 OLED shows a miniature outline of its own physical half,
mirrored and tucked one pixel from the top/outside edges. A solid 2x6 rectangle
represents the screen; the 30 switches, including encoder push, each have a
unique single-pixel position. Unpressed key positions stay blank. Short presses
remain visible for at least 100 ms.

The last resolved key name appears beside the outline, and its hexadecimal QMK
keycode appears at 35x8 pixels above the underline. Each half retains its own last
keypress. Releases and actions from the other half do not replace it. SpaceFN
taps show SPACE / 0X002C; holds show LT1 / 0X412C or LT2 / 0X422C after QMK
settles tap versus hold. Unknown actions retain exact hex with a KEY label.

The left screen has large CTRL / CAPS / ALT indicators. CAPS uses Caps Lock XOR
Shift. Active panels have rounded fills; inactive labels have no outlines.
The right screen retains its highest-active-layer number, including SpaceFN.
All six layers are imported from the saved VIA export.

The userspace previews are generated by the actual C renderer. The all-keys-lit
fixture matches the approved layout pixel for pixel; a second preview shows
sample pressed keys. All-keys-lit is only a test fixture, not a device mode.

## Modes and synchronization

Right encoder push [9,5] is reserved for Dashboard -> Rain -> Off -> Dashboard.
Dashboard enters rain after 60 seconds idle and wakes on activity. Held keys
prevent automatic idle entry. Manual rain stays selected while typing.

Rain uses minimum OLED brightness (0), restoring normal brightness on return
to the dashboard. Both automatic and manual rain power down after ten continuous
minutes. A fresh keypress wakes the dashboard after that timeout; held keys,
releases and encoder rotation do not. Manual Off still needs a mode press.

A validated custom split RPC carries physical key pixels, modifiers, Caps Lock,
layer, mode and per-half last-key codes. Attempts are capped at 40 per second,
with a heartbeat and throttled retries. This edition uses screen-state protocol
**2**, so both halves must run the matching firmware.

## Build and verification

With current QMK and external userspace configured:

```sh
qmk compile -kb cannonkeys/link -km svenge
qmk lint --strict -kb cannonkeys/link -km svenge
python ../qmk_userspace/tests/link/run_tests.py --preview
```

The artifact is `cannonkeys_link_svenge.uf2` in the external userspace directory.
Compilation, strict lint and host model/renderer/adapter tests passed using QMK
CLI 1.2.0 and ARM GCC 10.1.0. No automated flashing is performed; physical display
contrast, orientation and real split operation require keyboard verification.

CannonKeys' [Link build guide](https://docs.google.com/document/u/2/d/e/2PACX-1vTg0MTsDordDTWULn4RaYnWOafFsFO4yYKTXTK1zSvjai1oBfQnWYja18arVqZoE8eus836UWBVIfm0/pub)
identifies the outer/left USB port on the left PCB as the computer connection.
The other ports are the split interconnect. Establish the right PCB's actual
programming/recovery procedure rather than assuming its interconnect is a normal
USB programming port. QK_BOOT acts on the controller processing the keycode.

See the [userspace guide](https://github.com/svenski88/qmk_userspace/blob/feature/link-oled/keyboards/cannonkeys/link/keymaps/svenge/README.md)
for previews, source files, saved-layout import and test coverage.
